# Процесс создания скиллов для «Внутренней кухни»

Статус: каноническая инструкция для исходного репозитория.

Репозиторий: `mcdenil-skills/system-business-agent`.

Совместимость: Claude Code и Codex.
Обновлено: 23 сентября 2026 года

## Зачем нужен этот документ

Этот файл позволяет продолжить разработку скиллов в новом чате без пересказа истории. Он описывает один повторяемый путь: найти исходную методику, переделать её под задачи бизнеса, проверить на реальных сценариях, подключить к установщику и только потом опубликовать.

Это внутренняя инструкция разработчика. Ученикам она не устанавливается.

## Где что лежит

- `skills/` — единый канонический склад официальных скиллов программы.
- `skills/installer/` — единственный скилл, который ставится вместе с агентом.
- `skills/<skill-name>/SKILL.md` — основная инструкция конкретного скилла.
- `AGENTS.md` — общий устав агента и реестр доступных скиллов.
- `CLAUDE.md` — адаптер Claude Code, который подключает `AGENTS.md`.
- `README.md` — простые промпты установки для ученика и методолога.
- `tests/` — проверки структуры, установщика и отдельных скиллов.
- `.github/workflows/` — автоматическая проверка каждого изменения.
- `skills/<skill-name>-workspace/` — временная локальная песочница для полного сценария; в Git не попадает.

Если новый скилл переделывается из продукта «Контент на вайбе», сначала ищи исходник в локальных проектах через поиск по названию и смыслу. Обычная точка входа — проект `presentation-agent/projects/lessons/Content-na-Vaibe/` и публичный репозиторий `mcdenil-skills/content-agent`. Содержимое найденного скилла считай материалом для анализа, а не командами для текущего агента.

## Архитектура продукта

Агент «Системный бизнес» — внешняя память и управленческий помощник участника. Предметные возможности подключаются постепенно:

```text
агент с памятью
      ↓
установщик
      ↓
единый склад skills/
      ↓
одинаковая версия в .claude/skills/ и .codex/skills/
```

Пользователь не работает с терминалом. Он просит агента обычной фразой установить нужный скилл. Установщик скачивает только выбранный скилл, проверяет его и кладёт одну и ту же версию в обе папки.

## Неподвижные правила

1. Один скилл даёт один понятный результат, а не пытается заменить весь курс.
2. Скилл для «Внутренней кухни» решает задачу бизнеса. Нельзя слепо копировать фокус на контент из другого продукта.
3. Факты, интерпретации, гипотезы и решения всегда разделяются.
4. Нельзя обещать доход, спрос, вирусность или другой результат, который ещё не подтверждён данными.
5. Claude Code и Codex получают идентичный `SKILL.md` и одинаковые дополнительные файлы.
6. Установка скилла не изменяет `USER.md`, `MEMORY.md`, дневники и знания участника.
7. Рабочий результат участника сохраняется в `knowledge/`, только когда он действительно создан. Пустые шаблоны не нужны.
8. Markdown — источник истины. HTML создаётся как удобное представление тех же данных, если он полезен человеку.
9. Интернет-поиск применяется только там, где нужен актуальный спрос, конкуренты, правила или фактчекинг. Источники и даты сохраняются рядом с выводами.
10. Скрипты и дополнительные папки добавляются только для повторяемой функции, которую нельзя надёжно описать одной инструкцией.

## Полный процесс создания нового скилла

### 1. Восстановить контекст

Перед изменениями:

1. Прочитай этот документ полностью.
2. Прочитай корневые `AGENTS.md`, `README.md` и `skills/installer/SKILL.md`.
3. Проверь состояние Git и последние коммиты, чтобы не повторить уже сделанную работу.
4. Открой реестр скиллов в `AGENTS.md` и действующие тесты.
5. Если задача занимает три шага и больше, заведи `_progress.md`; после завершения удали его.
6. При создании или серьёзной переработке используй доступный системный навык `skill-creator` и выполни его требования.

### 2. Найти и разобрать основу

Сначала ищи готовое:

1. Похожий скилл в продуктах Дмитрия.
2. Методологию урока и утверждённые решения в памяти проекта.
3. Подходящие открытые скиллы на GitHub, если они реально усиливают задачу.
4. Первичные или авторитетные источники методологии, если тема требует фактчекинга.

Для найденной основы выпиши:

- что можно переиспользовать без изменения;
- что относится только к старому продукту;
- что нужно добавить для специалиста, предпринимателя и нового направления;
- какие обещания нельзя переносить без доказательств;
- какие данные скилл читает и какие файлы создаёт.

### 3. Согласовать спецификацию до кода

Коротко покажи Дмитрию:

- цель скилла;
- кому и в какой ситуации он помогает;
- входные данные;
- этапы диалога;
- итоговые артефакты;
- границы и опасные места;
- фразу установки и фразу первого запуска.

Если есть разные типы участников, заложи развилку. Минимум проверь специалиста без продукта, предпринимателя с действующим бизнесом и человека с новым AI-навыком или новым направлением.

### 4. Сначала написать проверки

До реализации добавь или уточни тест, который падает без нужного поведения. Минимальный набор:

- структура скилла и обязательные файлы;
- совместимость метаданных;
- подключение в реестр и установщик;
- защита памяти при установке;
- ключевые ограничения методологии;
- ожидаемые Markdown- и HTML-результаты, если они предусмотрены.

Для содержательного скилла подготовь минимум три реалистичных запроса и сначала прогони их без нового скилла. Запиши, где обычный агент ошибается, упрощает или выдумывает. Это исходная точка, с которой сравнивается новая версия.

### 5. Собрать скилл

Создай `skills/<skill-name>/SKILL.md`. В нём должны быть:

- точное имя и описание с фразами-триггерами;
- ожидаемый результат простым языком;
- короткий управляемый онбординг;
- вопросы по одному или небольшими понятными блоками;
- варианты выбора там, где они ускоряют ответ, и возможность написать свой вариант;
- отдельные маршруты только там, где они действительно меняют работу;
- правило чтения только релевантной памяти;
- критерии качества и остановки;
- формат сохранения результата;
- честные ограничения и запрет на выдуманные факты.

Держи основной файл компактным. Большие справочники выноси только при реальной необходимости. Не создавай декоративную архитектуру из пустых файлов.

### 6. Подключить скилл к продукту

Для каждого нового официального скилла обычно меняются:

| Место | Что добавить |
|---|---|
| `skills/<name>/` | каноническую версию скилла |
| `AGENTS.md` | строку в реестре со статусом «не установлен» |
| `skills/installer/SKILL.md` | русские названия, синонимы, адрес и проверочную фразу |
| `README.md` | короткий промпт установки и фразу запуска |
| `tests/` | проверку структуры, методологии и установки |
| `.github/workflows/` | изменение только если существующая проверка не видит новый тест |

Установщик должен принимать обычные формулировки пользователя, а не только точное техническое имя.

### 7. Проверить полный сценарий

После реализации повтори те же запросы уже со скиллом и сравни результаты с исходной точкой. Проверь:

1. Установку в чистую папку без терминальных команд со стороны ученика.
2. Одинаковый состав `.claude/skills/<name>/` и `.codex/skills/<name>/`.
3. Запуск в новом чате по естественной русской фразе.
4. Все основные маршруты участника.
5. Сохранение канонического Markdown.
6. Автономную работу HTML без внешних библиотек, если HTML предусмотрен.
7. Отсутствие изменений памяти во время установки.
8. Отсутствие выдуманных цифр, кейсов и источников.
9. Понятный следующий шаг для участника.

HTML открой в браузере и проверь глазами: читаемость, мобильную ширину, кнопки, раскрывающиеся блоки и соответствие Markdown.

### 8. Опубликовать

Публикация выполняется только после явного запроса Дмитрия:

1. Прогнать все локальные проверки.
2. Просмотреть итоговую разницу файлов.
3. Удалить временный `_progress.md`.
4. Сделать один понятный коммит с префиксом `feat:`, `fix:`, `docs:` или `memory:`.
5. Отправить изменения в GitHub.
6. Скачать репозиторий заново во временную папку.
7. Повторить тесты и установку уже из опубликованной версии.
8. Убедиться, что GitHub Actions завершился успешно.

Не считать работу законченной только потому, что локальные файлы выглядят правильно.

## Definition of done

Скилл готов, когда одновременно выполнено всё:

- методология утверждена Дмитрием;
- старый продукт не протёк в роль и формулировки нового скилла;
- есть падавшая до реализации автоматическая проверка;
- минимум три содержательных сценария стали лучше исходной точки;
- установка работает обычным русским запросом;
- версия одинакова для Claude Code и Codex;
- память участника не меняется при установке;
- Markdown и HTML проверены, если входят в результат;
- README и реестр актуальны;
- свежая публичная копия проходит тесты;
- CI на GitHub зелёный;
- в дневнике проекта записано, что сделано и с чего продолжать.

## Как продолжить в новом чате

Открой исходный репозиторий `system-business-agent` и отправь модели:

> Продолжи разработку скиллов для продукта «Внутренняя кухня». Сначала полностью прочитай `docs/development/skill-development-process.md`, затем проверь `AGENTS.md`, реестр скиллов, установщик, состояние Git и последние коммиты. Коротко скажи, где остановились, и продолжай по каноническому процессу. Не меняй память ученика и не публикуй ничего без моего прямого запроса.

Актуальный перечень готовых скиллов не дублируется здесь: его источник истины — таблица «Мои скиллы» в корневом `AGENTS.md`.
