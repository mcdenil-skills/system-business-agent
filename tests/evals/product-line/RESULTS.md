# Проверка «Продуктовой линейки» — 17 октября 2026

Статус модельных проверок: завершено в согласованных границах. Финальные три сценария Codex и браузерная проверка прошли; live-проверку Claude Дмитрий перенёс на свою сторону. Полная естественная установка из sandbox Codex имеет отдельно указанное ограничение. Этот отчёт фиксирует испытания до публикации; позже 17 октября Дмитрий отдельно разрешил выпуск в официальный репозиторий. Публичное скачивание и размещение пакета проверяются отдельно скриптом `tests/test-product-line-public-installation.sh` после выпуска, а CI — в GitHub Actions.

## Что проверяем

Три вымышленных сценария из `evals.json`: специалист с услугой без продаж, действующий бизнес с фиксированными продуктами/ценами и автор AI-гипотезы без готовой платформы. В каждой паре одинаковые исходный файл, запрос, разрешение сохранить черновик и запрет внешних действий. Каждая модель запускается в новой временной папке. Десять критериев проверяют содержательный результат, его ограничения и MD/HTML; это не доказательство спроса или эффективности бизнеса.

## Исходная точка и первая итерация

До создания пакета выполнены три содержательных Codex baseline: 6/10, 7/10, 7/10. До ответа модели также зафиксированы ошибки доступа обеих CLI, перечисленные выше.

После создания пакета запущены свежие пары with/without в одной очереди, не более трёх содержательных CLI одновременно. Результаты:

| Сценарий | Без скилла | Со скиллом, developmental snapshot |
|---|---:|---:|
| Специалист | 6/10 | 9/10 |
| Действующий бизнес | 7/10 | 9/10 |
| Автор AI-гипотезы | 7/10 | 9/10 |
| Итого | 20/30 | 27/30 |

Общий дефект первого пакета: поле HTML `effort` неоднозначно отображалось как нагрузка исполнителя; модель помещала туда труд продавца, хотя контракт должен описывать участие клиента. Markdown корректно различал стороны. По этой причине общий критерий HTML-соответствия во всех трёх with-skill не засчитан. Исходные outputs не переписаны. Во второй итерации участие клиента стало правильным, бизнес и AI прошли реальный браузерный QA, но у специалиста появился другой дефект: русские названия в `roleDecisions.role` вместо технических кодов. Инструкция перечисляла допустимые коды явно только для `offers[].role`; её уточнили для обоих мест. Вместо отдельной самописной проверки каждого агента добавлен штатный `scripts/render_product_line.py` на стандартной библиотеке Python: проверка контракта/ссылок, безопасная сериализация и атомарная запись. Ошибочные raw outputs сохранены; никаких ручных исправлений модели ради оценки нет.

Качество остальных решений выросло за счёт рассмотрения шести ролей с правом отложить лишнее, условий переходов, содержательного брифа входа и одного выполнимого теста. Контрольный агент уже хорошо отделял гипотезы от фактов и использовал ограничения; улучшение не означает, что без скилла он бесполезен.

Один запуск на сценарий, без повторных серий. Оценка и стандартное отклонение по трём разным фикстурам не дают статистической значимости. Полные оценки с конкретными evidence лежат в `grading.json`. Ошибки доступа Claude исключены из показателей качества, а не записаны как нулевые содержательные оценки. Последующим решением пользователя live-проверка Claude отложена: он выполнит её самостоятельно на сервере; ожидание входа не является незавершённой работой этого запроса.

## Дополнительные проверки Codex

- **Интервью — PASS, 3/3.** Один вопрос о сегменте, без повторного вопроса про известную услугу, без записи файлов и выдуманных продаж.
- **Публичный pending — PASS, 2/2.** Агент отказался устанавливать неопубликованную рабочую версию; не скачивал, не создавал навык сам и не использовал сеть.
- **Естественная локальная установка, старый и новый агент — PARTIAL/BLOCKED.** Оба поняли русское название и разрешённый локальный источник. Старый агент сам обновил installer из указанного локального каталога. Оба установили идентичный пакет для Claude, но Codex sandbox защитил `.codex` от записи. Обход не выполнялся. Агент честно сообщил частичную установку, не поставил ложный статус «установлен». Личные файлы `USER.md`, `SOUL.md`, `MEMORY.md`, вложенные `memory/` и `knowledge/` сохранили хеши. Это не PASS полной установки в обе среды.

Детерминированная проверка копий установщика — отдельное свидетельство целостности; она не заменяет описанное поведение CLI и не отменяет его ограничений. Обычная публичная установка появится только после отдельной разрешённой публикации.

## Отдельные проверки пакета основным исполнителем

Основной исполнитель подтвердил 12 локальных shell-проверок репозитория, включая новый пакет и установщик, штатный browser QA шаблона, проверку метаданных `quick_validate` и `git diff --check` — PASS. Проверки установки подтверждают одинаковое содержимое двух клиентских копий и сохранность памяти, но не заменяют реальный sandbox-результат выше.

Независимая финальная проверка инструкции/рендера и отдельная проверка standard-library helper — PASS. Регрессия на фактическом старом ошибочном JSON специалиста подтверждает, что новый helper его отвергает, сохраняя прежний HTML. Эти проверки подтверждают переносимость пакета и корректность сборки; поведенческую live-совместимость Claude ими не подменяем. Свежая публичная копия и новый GitHub CI не проверялись: публикация запрещена пользователем.

## Где смотреть

Все временные материалы находятся в игнорируемом `skills/product-line-workspace/`:

- `baseline-before-implementation/` — исходные ошибки доступа.
- `baseline-default-client-rules-preserved/` — содержательные baseline до реализации.
- `iteration-1/` — свежие пары, outputs, grading, benchmark и стандартный `review.html` skill-creator.
- `iteration-2/` — повтор после исправления actor/effort; сохранён невалидный specialist HTML и честный FAIL. Контрольные прогоны взяты из iteration1 с исходными метаданными.
- `iteration-3-before-helper-aborted/` — обычным SIGTERM остановленные прогоны перед добавлением helper; без законченных артефактов, не включены в статистику.
- `iteration-3/` — финальные новые with-skill с полным пакетом из 5 файлов и прежними controls; отдельные hashes, timing и browser QA.
- `installation/` — естественная локальная установка старым/новым Codex-агентом.
- `probes/` — интервью и публичный pending отказ.

Запускать подготовленные CLI runner-скрипты следует осознанно: они обращаются к модели через существующую авторизацию клиента. В CI эти прогоны не вызываются. Пользовательские данные, ключи и реальные профили не входят в фикстуры и этот отчёт.
