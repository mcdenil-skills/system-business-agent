# Проверка product-packaging

Дата: 2026-09-15. Проверены три учебных сценария, каждый со скиллом и без него.

| Сценарий | Со скиллом | Без скилла |
|---|---:|---:|
| HR-аудит без оплат | 7/7 | 6/7 |
| Новое AI-направление с одним пилотом | 7/7 | 6/7 |
| Нет выбранного продукта | 4/4 | 3/4 |

Итого: 18/18 против 15/18 содержательных проверок. Это результат небольшой учебной выборки, не гарантия поведения на любом запросе.

Два первых сценария использовали одинаковые заранее заданные ответы: вопросы, условия и согласия симулированы. Интервью и платежи синтетические, не реальные кейсы. Независимая оценка основана на выходных файлах и учебных журналах, а не на сыром журнале живой пользовательской сессии.

Основные отличия: вопросы по одному, полноценный интерактивный HTML в AI-кейсе и правильный переход к выбору продукта. Варианты без скилла также сохраняли многие факты, поэтому не все проверки отличают пользу навыка.

## Дополнительные проверки

- Chrome, локальный HTML без сервера: кратко/подробно, раскрытие, три копирования и ручной fallback.
- Мобильный экран 390px: нет горизонтального переполнения.
- Нет ошибок JavaScript и внешних сетевых запросов.
- Настоящий PDF из закрытых блоков: сохранились интервью/путь клиента в первом кейсе и платежи/поддержка во втором.
- Новый независимый контекст восстановил продукт, цену и незакрытые вопросы из памяти, без повторной анкеты.
- Локальные проверки структуры и размещения файлов в папках Claude/Codex пройдены; личная память при установке не меняется.
- Метаданные всех четырёх навыков проверены валидатором skill-creator.

Сетевой релизный сценарий запускается отдельно: `bash tests/test-product-packaging-public-installation.sh`. Он проверяет свежий клон, базового агента только с установщиком, выборочную загрузку навыка и совпадение двух копий без изменения памяти. Это проверка механизма установки, не автоматическая проверка интерпретации любого промпта моделью.

## Ограничения

Нет живой сессии Claude Code: проверены формат и идентичные файлы для обеих сред. Оформление будущих HTML создаёт модель, а не жёсткий шаблон; проверенные примеры не гарантируют безошибочности всех будущих карточек. Тайминги и токены среда не предоставила, их не сравнивали. Внутренние данные карточки могут попадать в печать: клиенту предназначен отдельный копируемый текст предложения.
